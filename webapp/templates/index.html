Configuration profile compare and apply a known-good parameter set

Capture read-only records of what the drive holds

Snapshot known reads the 31 parameters this package reasons about — a second. Scan discovers every parameter that exists on the drive by asking for each in turn: ~2,200 round trips, a few minutes, and the only way to capture a configuration you did not write. Both are read-only and cannot change anything.

Saved configurations compare, restore, or promote to a profile

A snapshot restores exactly like a profile does — same dry run, same backup-first, same read-back. Promoting one gives it a name and drops the parameters the firmware will never write, so a diff against it does not fill with rows that can never be actioned.

Live values

Writes are persistent — the same as editing on the keypad, with no undo. Group 53 (the serial config of this very link), 3018/3019 (the comm-loss watchdog), group 99 (the motor model) and groups 01–04 are refused by the PMC firmware at any time. Set those from the keypad, deliberately.
These move the fan. They are the steps that decide what the project can promise — run them in order, once, after wiring. Test section clear before any of them.

1 · Verify the calibration 10 min

The velocity-vs-RPM half is measured. Only the Hz→RPM link is assumed. One anemometer reading pins it down — you do not need the motor nameplate.

2 · Characterize 15 min

Step response → τ and the corner frequency. Saved to the config, so every profile afterwards is checked against it automatically. Run it twice: a positive step for the rising constant, a negative one for the falling constant — the falling one is what actually limits a symmetric gust.

3 · Frequency response optional, 20+ min

Measures attenuation across the band rather than inferring it from τ. Gives you the −3 dB bandwidth to quote.
